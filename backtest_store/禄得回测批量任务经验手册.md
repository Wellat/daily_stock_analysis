# 禄得网回测批量任务经验手册

- 整理日期：2026-10-06
- 来源：三策略回测与持仓落盘任务的实战复盘（详见同目录《执行复盘_三策略回测与持仓落盘_2026-10-06.md》），全部结论均经实测验证
- 用途：后续再做禄得网回测、批量持仓拉取、类似"大量串行 API 调用"任务时的操作与避坑参考

## 一、核心结论：大批量串行调用必须脚本化

**判断标准**（按调用量选执行方式）：

| 预计调用量 | 推荐方式 | 理由 |
|---|---|---|
| < 10 次 | 会话内直接调 MCP 工具 | 交互快，无需工程化 |
| 几十次 | 会话内循环 / 1 个子代理 | 尚可接受，但要防上下文膨胀 |
| **上百次及以上** | **独立 Python 脚本直连**（本手册方案） | 会话内调用的隐性成本此时爆炸 |

会话内逐次调用工具的隐性成本（本次实测）：

1. **慢**：经子代理链路单次调用 7.5~10.3 秒；脚本直连同样的调用只要 **~1.7 秒**（省去工具结果序列化进出上下文的开销）。
2. **耗配额**：每个子代理把每次 API 响应吞进自己的上下文，单个代理消耗 1,700万~3,500万 tokens；3 个代理就把子代理配额烧光（`exceed quota limit`），任务被硬阻塞。
3. **并发墙**：主机子代理并发上限 3，多派直接被拒（`user concurrency limit exceeded`）。
4. **不可续传**：子代理"报告写盘成功"≠ 交付（本次发生过代理写好的文件被外部删除而无人察觉）；脚本 + 断点文件天然幂等，重跑即续传。

**脚本直连的前提**：禄得 MCP 是 **HTTP 接入**（MCP-over-HTTP，JSON-RPC 2.0），端点与 Bearer 凭据已在本机 ZCode 配置（`~/.zcode/cli/config.json` → `mcp.servers.lude`）。stdio 型 MCP 服务则不适用此法。

## 二、现成工具：`scripts/lude_backtest_tools.py`

位置：`backtest_store/scripts/lude_backtest_tools.py`，零第三方依赖（纯标准库）。

```bash
# 试点：只拉前 10 个交易日，验证链路与落盘（强烈建议先做）
python3 backtest_store/scripts/lude_backtest_tools.py fetch \
  --backtest-id <回测ID> --name 策略1_无过滤 --limit 10

# 全量拉取（默认 2026-01-05 ~ 2026-09-30，断点续传，可反复执行）
python3 backtest_store/scripts/lude_backtest_tools.py fetch \
  --backtest-id <回测ID> --name 策略1_无过滤 --raw-dir backtest_store/raw

# 把 raw JSONL 展平为逐日逐标的持仓 CSV（Excel 可直接打开）
python3 backtest_store/scripts/lude_backtest_tools.py merge --raw-dir backtest_store/raw
```

要点：

- **凭据**：优先 `LUDE_URL` / `LUDE_TOKEN` 环境变量，其次自动读 `~/.zcode/cli/config.json`。不要把 token 写进代码、命令行或文档。
- **断点续传**：按已写入 JSONL 的 `trade_date` 跳过，中断/失败后重跑同一命令即可，天然幂等。
- **错误分类**：传输类错误（网络/超时/429/5xx）指数退避重试 3 次；业务错误（如 11025 该日无持仓详情）不重试、写占位行后继续。
- **交易日历**：内置 2026 年休市日（来源 `trading_calendar`）；其他年份用 `--days-file` 传入 JSON 数组。
- **积分**：`backtest_daily_position_get` 实测**不扣积分**（3 次探针前后余额均为 20）；`backtest_run` 的扣费规则未单独验证。

## 三、MCP-over-HTTP 直连的协议要点（自己写脚本时参考）

1. **握手**：`initialize`（带 `protocolVersion`，"2025-03-26" 不行就退 "2024-11-05"）→ 记住响应头里的 `Mcp-Session-Id` 并在后续请求带上 → 发 `notifications/initialized`（无响应体）。
2. **调用**：`tools/call`，`params: {"name": 工具名, "arguments": {...}}`。
3. **响应形态**：可能是纯 JSON，也可能是 SSE 流（`data:` 行）；解析器要两种都兼容，SSE 取最后一条 data。
4. **结果取值**：优先 `result.structuredContent`；没有则把 `content[].text` 当 JSON 解析。
5. **请求头**：`Accept: application/json, text/event-stream` 必须带，否则可能 406。

## 四、禄得平台契约坑位速查（均已实测）

| # | 坑 | 事实与解法 |
|---|---|---|
| 1 | `dictionary_query` 必挂（10901） | MCP schema 与下游序列化要求冲突，任何 key 都查不了。改从 `strategy_detail` 读已有策略取先例值（强赎 5 状态、评级档位、基准代码） |
| 2 | `screen_run` 报缺 parameters | 策略参数外面要再包一层 `{"parameters": {...}, "trade_date": "...", "answer_mode": 0}` |
| 3 | `ascending` 语义与字面相反 | `ascending=true` 时 rank1 是**因子值最大**的标的（截面实测 rank1 溢价率 272%）。「越小越好」传 `ascending=false`，且方向必须用历史截面验证 |
| 4 | 调仓参数不是平铺字段 | 用 `rebalance_method: {"rebalance_type": 0, "rebalance_value": N}` 表示每 N 个交易日；N 的生效需用换手率尖峰间隔验证 |
| 5 | `backtest_run` 响应截断 + 缓存 | 响应约 350KB，顶层键序每次随机，评估段常被 50KB 输出预算截断；同参数重跑返回字节级相同的缓存。解法：`capital` 微调几元绕缓存重掷键序，指标经济等价 |
| 6 | 回测不可并发 | 同用户同品种已有运行任务时返回 11080，必须串行 |
| 7 | 排除字段的语义 | `exclude_calls` 为 5 个中文状态全选；`公告不强赎`/`未到转股期` 不在排除范围内；`exclude_st` 是布尔；`exclude_ratings` 按评级档位列举 |
| 8 | 强赎停止交易无引擎特殊处理 | 不排强赎时，持仓会持有到下一换仓日并按最后收盘**冻结价**"卖出"（成交量 0 也成交）；判断看简称带 `Z` 前缀且 `last_price` 连日不动。低溢价策略约 7 成持仓期会进入此阶段，回测收益含乐观假设 |
| 9 | 净值曲线持仓滞后一天 | `timelines[].hold_securities` 比持仓明细 API 滞后一个交易日；以 `backtest_daily_position_get` 为准 |

## 五、批量任务四步纪律

1. **测算先行**：调用量 = 标的数 × 天数；乘以单次延迟（直连 ~2s）得出预计耗时，超过 10 分钟就必须脚本化 + 后台跑。
2. **试点验证**：先 `--limit 10` 跑通全链路（鉴权、落盘、格式），主上下文确认文件真实存在、行数正确，再全量。
3. **幂等续传**：输出用追加式 JSONL + 按日去重跳过；任何一步失败重跑整个命令即可，不要人工挑日期补。
4. **交付复核**：完成后在主上下文（而非执行者自己）验证：文件存在、行数 = 预期天数、首末日正确、抽查一行数值与已知净值吻合。

  --backtest-id 01a11059-b2a0-7312-a30d-bf33be1ce736 --name 策略2_排强赎 --raw-dir backtest_store/raw

# 策略3：排强赎 + 排A-以下评级（backtest_id: 01a11058-77c6-7842-a009-19c244dd7aa8）
